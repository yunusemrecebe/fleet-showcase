Problem

The handoff is the work

Analysis and tracker issues still need a split, a dependency order, and a review that is separate from the implementer.

An agent that takes every open issue also takes the wrong ones. A teammate may already own it. It may have no acceptance criteria.

Expected output: a spec, ordered tasks, tests, a review, and a pull request. A person decides the spec. Under the defaults, a person merges.

Agents

Roles, dependencies, separate reviews

Architect

Writes the spec and the task list for a module, story, or epic. A task or bug never reaches this role.

Developer

Plans and implements one ready task on a lane. The lane path accepts that plan.

QA

Sees the diff, the test results, and the spec title. Not the full spec. Not the developer transcript.

Security, then BA

Security uses the diff and test results only when the task is sensitive, and does not receive QA findings. BA triages what both return.

Prompt inputs are separated. This is not a separate machine.

Illustrative

A checked sequence, not a live delivery

Acceptance tests drive a fake tracker. The model and the git host are stubbed.

  • A module question parks. The next brief continues in the same tick.
  • Answered work resumes before any newer item.
  • With the pull-request gate on, Done follows a merge and green CI. That is the default Jira rule.
  • A restart does not duplicate the comments.
No product diff, test log, or pull request from a real run is stored in this repository.

Control

It keeps going, and it can resume

  • A question frees the lane. The answered item resumes first.
  • State is atomic. Continuations and an outbox survive a crash. Corrupt files are quarantined.
  • A person who moves a Jira issue wins. The base branch is not a push target.
  • Spec approval can time out into an approval. The daytime wait is 3 hours. Overnight it is 180 seconds.
  • A pull request opens after review. Merge stays with a person unless that switch is on.
